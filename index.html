odd-ws

Que tu agente no vuelva a cometer el mismo error

Un plugin que convierte lo que aprendes en un proyecto en chequeos que corren solos, en vez de notas que el agente tiene que recordar.

Para Claude Code, Codex CLI y gentle-shell (Pi). Código abierto, licencia MIT.

Versión actual: 0.13.3 · qué cambió en cada versión

Así se ve un bloqueo

Tu agente intenta git push --force origin main. El hook de comandos lo frena antes de que corra, y el agente recibe este mensaje:

guard-comandos bloqueó el comando: git push forzado (no lo corras tú: un lease sin `ref:sha` lo satisface cualquier `fetch`; para forzar con seguridad, el usuario mira `git log <remoto>/<rama>` y corre `git push --force-with-lease=<rama>:<sha que esperas> <remoto> <rama>`). Si la operación es deliberada, que la corra el usuario a mano.
Comando: «git push --force origin main»

Lo mismo vale para tu stack. Una capa es una tecnología de tu proyecto (SQL, C#, Android…) con sus reglas. Si el agente no cargó los no-negociables de la capa, su primera edición ahí se bloquea y los recibe, y después de cada edición corren las reglas de esa capa. El detalle está en Hooks.

Para quién es

Para quien trabaja en un proyecto con un agente de código y ya vio que repite los mismos errores. Según lo que ya uses, tu camino cambia:

Solo Claude Code

Instala el plugin completo: tickets, hooks por capa, writers con compuerta y revisión con recibo. Es el camino de Instalar.

Ya usas gentle-ai

Elige el perfil controles en el bootstrap: solo los guards, las reglas por capa y el doctor, sin tickets, writers ni revisión de odd-ws. Tu revisión sigue siendo la de gentle-ai y no se pisan.

Codex o gentle-shell (Pi)

Trabajan sobre la misma instancia. Una instancia puede usarse con varios CLI a la vez. Cada guía está más abajo.

Cómo funciona

Una convención que solo vive como texto depende de que el modelo la recuerde. odd-ws sigue el principio mecanismo antes que memoria: lo que se aprende se vuelve un chequeo, no un recordatorio.

1El agente comete un error
2Lo corriges en el ticket
3/odd-ws:cerrar lo gradúa
4Se vuelve un chequeo, una skill o un revisor
5Corre solo en el próximo ticket

Qué te da

  • Cada ticket tiene su carpeta, con su objetivo, sus criterios de aceptación y su alcance.
  • Los hooks chequean cada edición contra las reglas de su capa, y frenan los comandos peligrosos, también cuando el agente escribe por la shell.
  • Las reglas empiezan observando: una regla bloquea solo después de calibrarse contra tu código, y una disputada vuelve a avisar. Un falso positivo no te frena el trabajo.
  • Los cambios grandes los escriben agentes con compuerta, y los revisores dejan un recibo atado al diff. La revisión mide cuánto cuesta y explica por qué eligió su modo.
  • Lo aprendido en un ticket sube a reglas y docs verificables, y /odd-ws:cerrar memorias convierte en reglas las memorias del proyecto.
  • Las reglas de un stack se pueden traer de otro repo git, fijadas a una etiqueta, con /odd-ws:paquetes.
  • Puedes apagar un hook puntual con disabled_hooks, sin desinstalar el plugin.

Dónde va la instancia

odd-ws monta una instancia, un espacio de trabajo con agentes, en una carpeta aparte, al lado de tus repos de código. La instancia tiene su propio git y apunta a tus repos por su ruta, sin tocarlos.

mi-proyecto-ws/
La instancia: tickets, reglas, agentes y su propio git.
apunta por su ruta →
mi-proyecto/
Tu repo de código, intacto.

Si la creas dentro de un repo de código, la instancia no tiene git propio. En una subcarpeta, el bootstrap no le hace git init, ni configura el hook, ni hace el primer commit. En la raíz del repo, el bootstrap te pregunta antes y te recomienda una carpeta aparte: solo con tu sí la instancia queda en el git de ese repo.

Instalar

En video: la instalación con Claude Code, paso a paso, en 5 minutos y en español.

Necesitas Python y Git, y la versión mínima de tu CLI:

HerramientaVersión
Python, invocable como python33.7 o más. El doctor pide 3.11 o más para leer la config de Codex
GitEn Windows, Git for Windows
Claude Code2.1.284 o más; se recomienda 2.1.295 o más
Codex CLI, si lo usas0.144 o más; 0.167 o más para los writers
Pi, si lo usas1.5.0 o más. En Windows, sus hooks lanzan python
gentle-shell, para los writers en PiEl de npm i -g gentle-pi. Sin él, Pi corre los guards, pero no los writers

En Windows, python3 lo crean el Python install manager de python.org y la Microsoft Store, no el instalador clásico. El detalle está en el README.

Con Claude Code
  1. Crea la carpeta de la instancia, aparte de tus repos (puede estar vacía), y desde ahí instala el plugin. --scope project es obligatorio: sin él, los hooks correrían en todos tus proyectos. 
    claude plugin marketplace add sebasgc0399/odd-workspace-template
claude plugin install odd-ws@odd-workspace-template --scope project
    Si marketplace add falla con «its source doesn't match its extraKnownMarketplaces entry», el marketplace ya está registrado: sigue con plugin install.
  2. Abre claude en esa carpeta y corre /odd-ws:bootstrap. Detecta tus repos, te muestra la propuesta completa y solo escribe después de tu sí, con el primer commit incluido.
  3. Corre /odd-ws:doctor, arregla lo que marque FALTA y abre tu primer ticket con /odd-ws:abrir.

Antes de tu primer ticket, lee las reglas de la instalación: cada ticket lleva su propio .claude/settings.json y su sesión se abre con --add-dir.

Con Codex CLI
  1. Declara Codex en la instancia: "hosts": ["claude-code", "codex"] en workspace.config.json.
  2. Instala el plugin en Codex: 
    codex plugin marketplace add sebasgc0399/odd-workspace-template
codex plugin add odd-ws@odd-workspace-template
  3. Abre codex en la raíz de la instancia, confía en la carpeta y confía los hooks de odd-ws cuando Codex lo pida, o desde /hooks. Las skills se invocan con $, por ejemplo $doctor.
Con gentle-shell (Pi)
  1. Declara Pi en la instancia: "hosts": ["claude-code", "pi"], o solo ["pi"].
  2. Instala gentle-shell y el paquete de odd-ws. El paquete no está en npm: se instala desde git, con la etiqueta de la versión actual, y necesita npm en el PATH. 
    npm i -g gentle-pi
gentle-shell install git:github.com/sebasgc0399/odd-workspace-template@odd-ws--v0.13.3
  3. Abre gentle-shell en la raíz de la instancia, dale confianza con /trust y corre /skill:doctor. En una instancia que ya existía, el doctor genera los agentes de .pi/agents.

Junto a gentle-ai y engram

odd-ws no reemplaza a ninguno de los dos: cada uno cubre una parte distinta, y ninguno es obligatorio. Se pisan en una sola cosa, la revisión, y solo dentro de una instancia: ahí revisa odd-ws.

HerramientaDe qué se encarga
gentle-aiCómo trabaja el agente: el flujo, la delegación y la revisión
engramQué recuerda el agente entre sesiones
odd-wsQué se exige en cada proyecto, con lo aprendido convertido en chequeos
  • Con engram, /odd-ws:cerrar memorias lee las memorias del proyecto y te muestra cuáles vale la pena convertir en reglas.
  • Con gentle-ai, el doctor te propone apagar su revisión nativa solo en el clon de la instancia, y nunca la apaga solo. Si prefieres quedarte con la revisión de gentle-ai, elige el perfil controles: ahí no se pisan.

Novedades

0.13.3. El agente ya no puede forzar un push de ninguna forma, y cada bloqueo muestra el comando que frenó. La instalación se ve de un vistazo, con el comando de cada CLI listo para copiar.

0.13.2. Después de actualizar el plugin, la primera sesión pone al día la ruta del plugin en cada instancia y el doctor ya no queda en FALTA. El bootstrap llena siempre la fila de tu repo y describe sus comandos en español.

0.13.1. El bootstrap muestra lo mismo en cada corrida, con la pregunta de la raíz de un repo siempre igual, y vuelve a proponer tus repos como del equipo.

0.13.0. La propuesta del bootstrap deja a la vista lo que decides, el doctor se lee de un vistazo, una instancia nueva sale sin avisos y el aviso de calibrar trae un comando que se corre tal cual. Todo el texto de odd-ws pasa a tuteo neutro.

0.12.1. odd-ws le suma menos al prompt: nada en los subagentes de gentle-shell ni fuera de una instancia, y revisar y cerrar con un núcleo corto.

0.12.0. Instalar solo los controles, apagar un hook puntual, y reglas por capa que bloquean solo después de calibrarse. Si actualizas, calibra tus reglas: hasta entonces solo avisan.
